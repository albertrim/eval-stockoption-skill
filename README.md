# ipo-eval

**우리 회사가 코스닥에 상장하면 내 스톡옵션은 얼마일까** — 최근 5년 코스닥 상장 실데이터로
계산해 Threads에 바로 올릴 글로 만들어 주는 Claude Code 스킬.

> 재미로 보는 계산기입니다. 투자·세무·법률 자문이 아닙니다.
> 옵션 행사, 주식 매매, 이직 판단에 쓰지 마세요.

## 무엇을 하나

회사 질문 여덟 개, 스톡옵션 질문 일곱 개. 답하고 나면 이런 글이 나옵니다.

```
🏢 우리 회사가 코스닥 가면?
· 상장 가능성 64% · 거래소 예비심사 청구
· 예상 상장 2027년 상반기
· 예상 시총 1,496억원
· 주당 25,582원

내 스톡옵션 5,000주 중 상장 시점 행사 가능 2,500주 (행사가 3,000원)
· 세후 손에 쥐는 돈 5,633만원
· 오늘 기준으로 당기면 5,573만원
· 지분 0.04%

⚠️ 재미로 보는 추정. 최근 코스닥 상장 IT·소프트웨어 20곳 기준.
#스톡옵션 #코스닥 #IPO
```

**메인 글의 숫자는 기준 시나리오 하나입니다.** 폭은 첫 답글에 들어갑니다.

```
[범위] 위 숫자는 기준 시나리오 하나입니다. 시총 374억원~3,117억원,
주당 6,395원~53,310원까지 벌어집니다(비교기업 배수 하위 10%~상위 90%).
최악·최선이 아닙니다.
같은 폭으로 세후 가치는 846만원~1억2,551만원입니다.
```

답글은 4개입니다. 비교기업 목록, 범위와 계산에 쓴 가정, 상장 가능성의 근거,
행사 비용과 6개월 뒤 시나리오.

## 설치

Claude Code 플러그인입니다. 대화창에서 두 줄이면 됩니다.

```
/plugin marketplace add albertrim/eval-stockoption-skill
/plugin install ipo-eval
```

`python3` 3.10 이상만 있으면 됩니다. 설치할 패키지는 없습니다.

| 이렇게 치면 | 무엇이 시작되나 |
|---|---|
| `/ipo-eval:company` | 회사 모드 — 질문 8개 |
| `/ipo-eval:option` | 옵션 모드 — 질문 7개 |
| `/ipo-eval:company 회사이름` | 회사 이름까지 한 번에. 질문 1번을 건너뜁니다 |
| "우리 회사 코스닥 가면 얼마야" | 회사 모드 |
| "내 스톡옵션 얼마야" | 옵션 모드 |

옵션 모드는 회사 모드 결과 위에서 돌아갑니다. 저장된 회사가 없으면 회사 모드부터 하자고
알려줍니다.

### DART 자동 조회 (선택)

회사 이름을 넣으면 DART 전자공시에서 **설립연도·매출·영업손익·발행주식수**를 찾아 자동으로
채웁니다. 그만큼 질문이 줄어듭니다. 감사보고서나 사업보고서를 내는 회사면 대개 잡힙니다.

쓰려면 [opendart.fss.or.kr](https://opendart.fss.or.kr)에서 키를 무료로 발급받아 넣으세요.

```bash
echo "발급받은키" > ~/.ipo-eval/dart_key
```

키가 없거나, DART에 그 회사가 없거나, 보고서에서 숫자를 못 읽으면 **아무 말 없이 원래대로
직접 물어봅니다.** 못 믿을 값은 버리고 묻습니다 — 표 단위를 잘못 읽었거나(매출 1억 미만),
당기와 전년이 같은 값이거나, 영업손익이 매출의 3배를 넘는 경우입니다.

사명이 바뀐 회사도 찾습니다. DART 등록명이 옛 이름이어도, 새 이름으로 넣으면 잡습니다.

직접 확인해 보려면:

```bash
python3 scripts/ipo_eval.py dart --name 회사이름   # 저장소 폴더에서
```

## 내 정보는 어디로 가나

입력한 회사·옵션 정보는 **`~/.ipo-eval/`에만 저장됩니다.** 바깥으로 나가는 요청은 둘뿐이고,
둘 다 읽기만 합니다.

| 어디로 | 무엇을 | 언제 |
|---|---|---|
| GitHub raw | 공개 데이터 파일, `VERSION` | 업데이트 확인·적용 |
| DART 오픈API | 회사 이름으로 공시 조회 | DART 키를 넣었을 때만 |

DART 조회는 **회사 이름만** 보냅니다. 매출·옵션 수량 같은 입력값은 보내지 않습니다.

지우려면 `rm -rf ~/.ipo-eval` 하면 됩니다.

```

  ipo_eval.py       CLI (표준 라이브러리만)
  lib/              계산 엔진 — 비교기업·확률·밸류·옵션·세금·포맷·DART
  tests/test_all.py python3 scripts/tests/test_all.py
```

데이터를 직접 다시 만들려면:

```bash
cd builder && uv sync
DART_API_KEY=... uv run python build.py --years 5
uv run python backtest.py
```

## 새 버전 내보내기 (관리자용)

사용자 쪽은 세션에서 처음 스킬을 부를 때 `update check`를 돌립니다(24시간에 한 번).
무엇이 새 버전인지는 두 값으로 각각 판정합니다.

| 무엇 | 사용자가 가진 값 | 저장소에서 읽는 값 |
|---|---|---|
| 스킬 코드 | 설치 폴더의 `VERSION` | `main` 브랜치의 `VERSION` |
| 비교 데이터 | `manifest.json`의 `data_version` | `data/manifest.json`의 `data_version` |

**코드만 고쳤으면 `VERSION` 한 줄만 올려 push하면 됩니다.** 사용자에게 바로 잡힙니다.
`data/manifest.json`을 다시 만들 필요는 없습니다.

```bash
echo "0.3.0" > VERSION
git commit -am "..." && git push
```

데이터를 새로 뽑았으면 빌더가 `manifest.json`의 `data_version`을 갱신하므로, 그것까지
같이 push하면 됩니다.

사용자가 `y`를 누르면 `update apply --data --skill`이 돌아갑니다. `--skill`은 설치 폴더에서
`git pull --ff-only`를 합니다. 플러그인은 git clone으로 설치되니 그대로 동작합니다.
`/plugin update ipo-eval`로 받아도 됩니다. 어느 쪽이든 `~/.ipo-eval/`의 프로필은 건드리지 않습니다.

`.claude-plugin/plugin.json`과 `marketplace.json`의 `version`도 `VERSION`과 같이 올려주세요.
이 둘은 Claude Code의 플러그인 관리 화면에 보이는 값입니다.

## 버전

### 0.6.0 (2026-09-05)

**비교기업이 엉뚱하게 잡히던 것을 고쳤습니다.** 물류·풀필먼트·창고·배송은 `industrial`
입니다. 데이터를 만들 때는 `운송`·`물류`를 `industrial`로 분류하는데 스킬의 업종 표에는
그 말이 없어서, 풀필먼트 회사가 `ecommerce_platform`으로 들어가 화장품·콘텐츠 상장사와
비교되고 있었습니다. 같은 회사로 재보면:

| 업종 | 비교기업 | 조건 확장 | PSR 폭 |
|---|---|---|---|
| `ecommerce_platform` (이전) | 5곳 | **4단계** (매출 10배까지) | 2.6~27.2배 |
| `industrial` (지금) | 5곳 | **0단계** (매출 3배 이내) | 2.7~6.1배 |

코스닥 상장사 339곳 중 물류로 잡히는 곳은 1곳뿐이라 별도 업종은 두지 않았습니다.

**조건을 몇 단계 넓혔는지 결과에 적습니다.** 이전에는 "표본이 모자라 조건을 넓혔습니다"
한 줄이라 4단계나 넓힌 것이 안 보였습니다. 3단계 이상이면 업종군까지 넘어간 표본이라고
함께 적습니다.

**청구 전 단계 확률은 5% 단위로만 냅니다.** 근거 데이터가 없는 계수를 곱한 값이라
1% 단위를 붙이면 없는 정밀도를 파는 것입니다. 계수에 데이터가 없다는 사실도 결과 문장에
그대로 적습니다.

### 0.5.0 (2026-09-05)

**"상장 6개월 뒤에 판다면"이 한쪽만 보여주던 것을 고쳤습니다.**

- **수량** — 상장일 기준이 아니라 6개월 시점에 행사 가능해진 물량을 씁니다. 그 사이 더
  가득되는 분도 팔 수 있는데 빠져 있었습니다
- **주가** — 중앙값 하나가 아니라 하위 25%~상위 25%를 함께 냅니다. 최근 상장사 314곳의
  6개월 수익률은 p25 −47.5% · 중앙값 −16.3% · p75 +34.4%로 갈리고 37.9%가 공모가를
  넘겼습니다. 중앙값 −16%만 적으면 음수 하나가 결과의 전부가 됩니다

비교기업이 5곳 미만이면 분포를 내지 않고 중앙값 문장으로 되돌아갑니다.

### 0.4.0 (2026-09-05)

**바뀐 것 — 상장 가능성이 흑자 여부를 반영합니다**

승인율·상장률을 흑자/적자로 나눠 씁니다. 최근 5년 청구 455건 기준:

| 표본 | n | 청구 시 상장 확률 |
|---|---|---|
| 흑자 | 240 | **75.8%** |
| 적자 | 215 | **63.7%** |
| (이전: 전체) | 455 | 70.1% |

**업종별 분리는 없앴습니다.** 같은 455건을 leave-one-out으로 채점하니 업종별
(Brier 0.2129)이 분리 없음(0.2105)보다 나빴습니다. 흑자 여부(0.2077)만 개선됐고,
업종+흑자(0.2138)가 가장 나빴습니다 — 셀의 절반이 30건 미만이라 노이즈를 확률로
내보내게 됩니다.

개선 폭은 Brier 기준 1.3%로 크지 않습니다. **확률의 큰 불확실성은 여전히 청구 전
단계 계수(`PRE_FILING_FACTOR`)에 있고, 그건 데이터가 없는 가정값입니다.**
자세한 근거는 [`references/methodology.md`](references/methodology.md) §4에 적었습니다.

### 0.2.0 (2026-09-05)

**바뀐 것**
- **DART 자동 조회.** 회사 이름을 받으면 바로 감사보고서·사업보고서에서 설립연도·매출·
  영업손익·발행주식수를 가져와 채웁니다. 질문 8개 중 최대 4개가 줄어듭니다.
  키가 없거나 못 읽으면 조용히 원래 질문 흐름으로 돌아갑니다
- **메인 글은 기준 시나리오 하나만** 보여줍니다. 시총·주당가·옵션 가치 모두.
  보수~낙관 폭은 답글의 `[범위]` 줄에 그대로 남습니다
- **이익이 얇으면 PER을 쓰지 않습니다.** 순이익이 매출의 3% 미만이면 자동으로 매출
  배수(PSR)로 계산하고 그 이유를 적습니다. 묻지 않습니다

**고친 것**
- 흑자 전환 첫 해처럼 이익률이 얇으면 시총이 10분의 1로 무너졌습니다. 매출 1,000억·
  순이익 10억인 회사의 기준 시총이 268억원으로 나왔습니다 (지금은 2,990억원)
- 데이터만 갱신해도(`update apply --data`) 스킬 코드가 최신인 것처럼 표시됐습니다.
  `manifest.json`이 통째로 덮어써지면서 그 안의 `skill_version`까지 새 값이 됐기
  때문입니다. 이제 설치 폴더의 `VERSION`을 직접 봅니다
- 채팅으로 받은 숫자를 되읽어 확인하고, 한 질문에 답이 둘 이상 오면 어느 값인지
  확정받도록 했습니다

### 0.1.0 (2026-09-05)

첫 공개.

**기능**
- 회사 모드 — 상장 가능성, 예상 시총·주당 가격 3시나리오. 질문 8개
- 옵션 모드 — 행사비용·세후가치·현재가치, "상장 6개월 뒤에 판다면" 시나리오. 질문 7개
- Threads 메인 1개(500자 이내) + 근거 답글 4개
- 데이터·스킬 업데이트 확인 (첫 실행 시 y/n, 24시간에 한 번)

**데이터**
- 최근 5년 코스닥 직접공모 상장사 339곳, 예비심사 청구 이력 2,107건, 현재 심사 중 58곳
- 상장 확률은 실제 청구 이력에서 계산. 청구 전 단계만 가정 계수
- 세율·한도는 2026년 기준으로 확인하고 값마다 출처 URL 기재
- 상장예정주식수는 83%를 DART 증권신고서에서 직접 파싱

**모델을 믿을 수 있게 만든 장치**
- 백테스트(336곳 leave-one-out) 결과를 결과 화면에 그대로 표시 — 시총 오차 중앙값 50%,
  보수~낙관 범위 적중률 70%
- 시나리오 폭을 사분위(적중 41%)에서 하위 10%~상위 90%(적중 70%)로 넓힘
- 예상 시총이 코스닥 형식요건 최저선(90억원)에 못 미치면 확률을 5%로 내리고 이유를 표시
- 매출 30억원 미만이면 매출 배수 대신 업종 시총 분포를 쓰고, 그 사실을 밝힘.
  회사 규모가 상장 표본과 동떨어지면 시총을 아예 내지 않음
- 심사가 중앙값의 2배 넘게 길어진 건은 확률을 감쇠
- 옵션 수량이 발행주식수를 넘으면 계산을 거부
